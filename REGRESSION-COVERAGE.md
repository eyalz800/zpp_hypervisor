# Regression coverage

Which defects this project has fixed, and which of them a test would catch
if they came back.

An audit of the full history of `origin/develop` - 576 commits, bodies read
in full, plus all of `BACKLOG.md` and `CLAUDE.md`. Commit bodies matter here
rather than subjects: this tree records the mechanism, the measurement and
the citation in the body, and roughly a third of the defects below are in
commits whose subject line says `docs:`, `diag:`, `feat:`, `perf:` or
`test:` rather than `fix:`.

**The whole table is here, gaps included.** The list of fixes with no
regression test is the useful half of this document, and it is never
filtered down to the ones somebody got round to covering. A row that says
`untestable-here` says what would be needed instead; a row with no reason at
all would be worse than no row.

## What has changed since the audit was taken

The audit's finding is at the top of the next section and it reframes every
"covered" verdict: the tests that existed did not run. That is fixed.

- `scripts/ci/run-host-tests.sh` runs every hosted harness and every
  source-level check in one command, and a `host-tests` job runs it. Four of
  the eleven did not compile when it was first written - three harness shims
  had drifted from `hypervisor.cpp` and one decoder assertion was still
  asserting behaviour the decoder had deliberately stopped having.
- `tests/elf_relocate/` covers the `elf_file::relocate` trait bug (entry 1 of
  the ranked list below), plus `DT_RELASZ` as a byte count, `PT_DYNAMIC`
  found by type, and the zeroed `.bss` tail. A `static_assert` in
  `elf_file.h` pins the trait spelling itself.
- `scripts/ci/check-exit-handler.sh` states the rule "nothing a guest can
  execute may reach `default:`" rather than its instances, and found that
  **GETSEC has no case** - see its output for why CPUID concealment does not
  close that.
- `uefi_loader/include/zpp/guest_tests.h` and
  `scripts/ci/bochs-exit-coverage.sh` cover the exit handler, EPT and the
  store emulation end to end, from inside the guest, graded against the SDM.
  106 cases, 21 of 60 exit reasons reached, and the 39 not reached are
  printed in full every run. Eleven more cases assert the *negative* - that
  an instruction whose exiting control this VMM does not set really does not
  exit - which a reached-reason count cannot show and which is what turns a
  control enabled by accident into a clean failure rather than a wedged
  processor.
- `tests/local_apic/` covers the interrupt command register's decode: the
  three defects fixed inside `on_interrupt_command`, every delivery mode,
  every shorthand, and the slot allocator.
- `tests/nested_vmx` section 13 and five source-level invariants in
  `check-exit-handler.sh` cover **what the capability MSRs advertise against
  what is implemented** - the largest instance in this tree of the
  "answering part of an interface" failure mode, since a guest hypervisor
  reads those MSRs once and builds a VMCS and its own page tables on them.
- `tests/mtrr/` covers the memory-type derivation the EPT builder depends
  on. Under EPT the guest's own MTRRs are not consulted by hardware, so
  what this derives is the only memory type the guest's address space has,
  and a wrong answer is cached MMIO rather than a slow one.
- `tests/ap_start_up` covers `apply_start_up`: SDM Table 12-1's INIT state
  including the CR0 footnote that CLAUDE.md records three positions being
  held on in one afternoon, and the duplicate-SIPI guard with the launch
  exemption that cost one processor of eight per boot.

Everything else below is still open. The ranked list at the end is the order
to take it in.

## The finding that reframes every "covered" verdict below

**None of the five `tests/*` harnesses runs in CI. Six of the eight
`scripts/ci/*.sh` checks are never invoked by anything at all.**

`.github/workflows/ci.yml` has five jobs, and between them they run exactly two
of the twelve check scripts: `check-invariants.sh` (from `build`) and
`bochs-smoke.sh` (from `bochs-vmx`). `check-decoder.sh`, `check-instruction.sh`,
`check-nested-ept.sh`, `check-nested-absent.sh`, `check-diag-absent.sh` and
`bochs-nested.sh` are invoked by no workflow, no CMake target and no other
script. There is no `ctest` registration, no `tests/run-all.sh`, no Makefile —
no single command runs the suite.

So roughly **11,000 lines of assertions** — the decoder differential against
LLVM, the nested-exit differential against KVM, the watched-page path, the AP
start-up concurrency invariants and the nested VMX state machine — run only
when somebody remembers to type `build.sh`. `check-nested-absent.sh`'s baseline
hash and `check-diag-absent.sh`'s zero-cost claim, both of which exist
specifically to make a silent regression loud, are unenforced in practice.

Read every "**yes** — `tests/…`" below as *"a test exists that would catch
this, if anyone ran it."* Wiring them in is a smaller job than any single test
in the ranked list at the end, and it multiplies all of them.

Two further caveats inside the coverage that does exist:

- `tests/ap_start_up` invariant 1 ("one VMCS per processor") is **self-declared
  a regression pin that does not reproduce** the original defect — with both the
  store and the load in one function the compiler forwards one to the other.
- `tests/nested_exit` and `tests/watched_page` have a `diverge()` mechanism that
  deliberately asserts the **current wrong answer** so that a fix flips the check
  and forces the entry to be deleted. Three of those are live defects with named
  smallest fixes (below).

## TOP 12 CHEAPEST HIGH-VALUE TESTS TO WRITE

Ranked by (probability of regression) × (cheapness). A one-token trait or one
bit ranks far above a structural rewrite.

**0. Before any of these: wire the five existing harnesses and the six orphaned
`scripts/ci` checks into `ci.yml`.** This is not a test to write — it is the
single cheapest action on this list and it multiplies every other entry. Eleven
thousand lines of assertions, including three that already encode named live
defects and one (`check-nested-absent.sh`) whose entire purpose is to make an
unintended byte change loud, currently run only when somebody remembers. Two

`llvm-mc`/`llvm-objdump` on PATH, and a machine without them must **fail**, not
skip — a skipping test here is the same failure mode as the bug it guards.

1. **`elf_file::relocate` — RELA must not take the REL branch.**
   *Assert:* relocating a synthetic RELA image at base `B` leaves each slot at
   `B + r_addend`, never `B`; plus `static_assert(std::is_same_v<relocation_kind, elf_rela>)`
   inside the RELA branch and the matching one for REL.
   *File:* `hypervisor/include/zpp/elf_file.h`. *How:* `host-unit`, ~40 lines.
   *Why first:* one trait spelling, silent for the entire life of the project,
   and the failure mode (`#UD` at a tiny offset from the module base) cost a
   full debugging session. A `constinit`-only codebase never exercises its own
   loader, so nothing else will ever catch it.

2. **A DWARF-derived layout module for `scripts/*.py` — and the first thing it
   catches is already broken.**
   *Assert:* every struct offset, member size, array capacity, element stride
   and **member order** any script uses equals what the built ELF's DWARF says;
   a synthetic-memory round trip decodes `exit_reason_counts` correctly for a
   **non-zero** cpu index; and a renamed member raises rather than returning
   zero.
   *File:* `scripts/rig-dump-state.py`, `scripts/read-disk-log.py`.
   *How:* `python-unit` — and there are **no Python tests in this tree at all**
   today, so this is also the file that makes the next one possible.
   *Why:* `ecc4b70`, `7a85e7a` and `9a6dae9` are three instances of one bug in
   one file, and none of them *failed* — each answered. Three more are live
   right now: `dump_field_use(capacity=128)`, `vm_entry_failure` read as 6 words
   when it is 18, and the positional 8-tuple that encodes member order. The
   cpu-0-cancels property is why the test must use a non-zero cpu index or it
   passes over the very bug it exists for.

3. **`segment_descriptor` → VMCS translation.**
   *Assert:* `vmx_access_rights` masks bits 11:8 to zero; `effective_limit`
   scales by the granularity bit. Table-drive real firmware descriptors.
   *File:* `hypervisor/include/zpp/arch/x86_64/descriptor.h` (+ `setup_vmcs`).
   *How:* `host-unit`, ~30 lines.
   *Why:* `793026a` — two independent one-bit mistakes that made VM entry
   reject guest state outright, in a pure function with no target dependency.

4. **Control-register masks and fixed-bit arithmetic.**
   *Assert:* `cr0_guest_host_mask` and `cr4_guest_host_mask` are both written;
   CR0's contains NE; CR4's contains VMXE; the CPUID VMX bit and the CR4 read
   shadow are keyed on the same constant; and the FIXED0/FIXED1 masks are
   64-bit throughout.
   *File:* `hypervisor/src/hypervisor/hypervisor.cpp` (`setup_vmcs`).
   *How:* `host-unit` + `bochs-invariant`.
   *Why:* four separate defects here (`1eca37b`, `a14f114`, `491d0b6`,
   `0ca32e6`), three of them a *missing* write whose absence made a neighbouring
   correct write inert — the single most repeated shape in this history.

5. **The ESP reservation's integer arithmetic.**
   *Assert:* idempotency against the **clamped** request; the total may only go
   down; the gap is at most the configured size plus one cluster; and
   `block_size / target.block_size` is never zero.
   *File:* `uefi_loader/src/esp_reservation.cpp`.
   *How:* `host-unit` over a synthetic BPB.
   *Why:* `17a2715`, `3721f3e` and all four of `b3c74be`. One of them
   (`log_target::usable` accepting an 8 KB logical block) issues a **512 MB
   write into somebody's EFI system partition**. Pure integer arithmetic, no
   firmware.

6. **MTRR → EPT memory type derivation.**
   *Assert:* `IA32_MTRR_DEF_TYPE`, the eleven fixed-range registers and the
   variable pairs are all consulted; SDM 14.11.4.1 precedence including
   UC-wins independent of visiting order; a range starts at
   `PhysBase & PhysMask`; a zero `PhysMask` is invalid, not "matches
   everything ≥ base".
   *File:* `hypervisor/include/zpp/arch/x86_64/mtrr.h`.
   *How:* `host-unit`.
   *Why:* `63a5d17` and `83012e7`. Under EPT hardware ignores the guest's own
   MTRRs, so a wrong type here is the *only* type the guest's physical address
   space has — write-back MMIO. The commit's model was written and thrown away.

7. **"Nothing a guest can execute may reach `default:`."**
   *Assert:* every basic exit reason SDM 28.1.2 makes unconditional has a case;
   ideally via a `-Werror` exhaustive `switch` over the reason enum so it is a
   compile error rather than a grep.
   *File:* `hypervisor/src/hypervisor/hypervisor.cpp` exit handler.
   *How:* `bochs-invariant`.
   *Why:* this rule has been broken **five** times — the thirteen VMX
   instructions (`3afbaa7`/`8412b76`), MSRs (`92f0457`), MOV to CR0
   (`a14f114`), exit reason 52 (`737b754`), and INIT/SIPI (`d893bb9`) — and once
   by a different route entirely (`6a1585e`'s `return false`). Each cost a boot.

8. **The one-token identity rule: VPID is the slot.**
   *Assert:* `setup_vmcs` writes `vpid(cpu + 1)`; nothing derives an identity
   from `next_virtual_processor`; and under concurrent launches in
   `tests/ap_start_up`, `vpid() - 1 == slot` for every processor.
   *File:* `hypervisor.cpp`.
   *How:* `bochs-invariant` + extend `tests/ap_start_up` (`host-unit`).
   *Why:* `c98c0f8` and `d423b9e`. The failures are all silent
   misattribution — one processor's exits in another's ring, a flag cleared at
   one index and tested at another — and it "worked" only while processors
   happened to launch in slot order.

9. **A header-compiles translation unit.**
   *Assert:* a single TU includes every header in `hypervisor/include` and
   `uefi_loader/include`, compiled with the real flags; plus `llvm-nm -u` empty
   for **all four** targets rather than the hypervisor alone.
   *How:* `bochs-invariant`, one file plus one CI step.
   *Why:* `5aa497a` — a header that had never been included and could not
   compile — and `5d5704f`, an undefined symbol in the one target the ELF
   invariant check does not cover.

10. **Policy switches must match their own comments.**
    *Assert:* every `constexpr bool` in `diag/config.h`, `nested_vmx.h` and
    `power.h` whose comment says it is off is off, by `static_assert`.
    *File:* `hypervisor/include/zpp/diag/config.h` and neighbours.
    *How:* `bochs-invariant`.
    *Why:* three separate commits (`14e53da`, `6614d5b`, `14abf97`) fix a switch
    committed in the state its own comment forbids — one of which had been
    writing a proof block into the ESP among real boot files on every debug
    build ever booted.

11. **NVMe queue arithmetic and encodings.**
    *Assert:* Set Features (Number of Queues) uses zero's-based `FFFEh`, not
    `FFFFh`; a completion is matched by command identifier, never by "any
    completion"; the queue's tail, head and phase travel with the storage; and
    the block header's signature is at offset zero and survives a write.
    *File:* `hypervisor/include/zpp/nvme/queue_pair.h`, `diag/esp_blocks.h`.
    *How:* `host-unit` with a modelled controller in host memory.
    *Why:* `b9102ca`, `d68b251`, `8b3f658`, `7b0b919`, `03578ab` — five
    defects, all pure arithmetic, none reproducible on either emulator, all
    against somebody's real disk.

12. **XSETBV operand and CPL.**
    *Assert:* the value is `EDX:EAX` with both high halves ignored; CPL comes
    from bits 6:5 of the guest SS access rights; a non-zero CPL injects `#GP`

    *File:* `hypervisor.cpp` `on_xsetbv`.
    *How:* `host-unit`, ~20 lines.
    *Why:* `22341a4` — three bugs in one expression, the worst of which is a
    guest-triggerable permanent halt of a physical CPU from ring 3.
