# The number of VM exit reasons the guest coverage suite must reach.
#
# scripts/ci/bochs-exit-coverage.sh fails when a run reaches fewer than
# this, and says so when a run reaches more. Coverage may go up and may
# not go down.
#
# Why a floor and not an exact count: a run that reaches *more* than this
# is a run somebody has improved, and failing it would make improving
# coverage cost a second commit before the first one could be green.
# Raising it is the second commit, and the message above is the reminder.
#
# Why a file and not a constant in the script: raising it is then a diff
# that says what it raised and by how much, in a file whose whole content
# is that number. The same argument nested_vmx.h makes for a plain
# constant over a CMake option - a switch that changes what is graded
# should appear in the diff.
#
# Measured under Bochs 3.0 built --enable-vmx=2, one processor, debug and
# release both, on 2026-08-12: 23 reasons reached. The rest carry a
# disposition in the coverage table in uefi_loader/src/guest_tests.cpp
# saying why, and reaching them is open work rather than a closed
# question - see that table.
#
# The denominator used to be written here as 60, and it was wrong: the
# table had sixty rows and Appendix C defines seventy-nine. 22 of 60 was
# never the number.
#
# 22 -> 23. The new one is reason 33, VM-entry failure due to invalid
# guest state, reached by `nested.injection_refused_by_hardware` now that
# ZPP_NESTED_VMX is on by default and the nested probe runs. Its
# disposition in the table is still the `out-of-scope:` one - a failed
# entry means the guest does not run, so there is nothing inside it to
# report with - and the case that reaches it overrides that at runtime
# through `session::why`, which is what that mechanism is for.
#
# Worth knowing what it is measuring, because it is not a success: the
# probe builds its vmcs12 with `guest_rflags = 0x2` and then asks for an
# external interrupt to be injected, which SDM 29.3.1.4
# (.references/sdm.txt:202582) forbids - IF must be 1 for that event
# type. The processor is right to refuse the entry, and the reason is
# reached because a test is wrong rather than because a path is
# exercised. Fixing the probe would *lower* this number by one, which is
# the correct trade and needs this floor lowered in the same commit.
#
# Raised the moment the job asked for it, which is the only moment
# anybody is looking: both CI configurations printed "COVERAGE ROSE - 23
# reached against a floor of 22" on run 31542068588, and a local run
# agreed at 23 of 79.

floor=23

# The number of rows the coverage table must have, and it is exact rather
# than a floor.
#
# The floor above grades the numerator and nothing grades the
# denominator, which leaves one way to make the report look better
# without improving anything: delete a row. A reason with a `plan:`
# disposition costs nothing to remove, no check above notices - the
# disposition gate only reads rows that exist, and `observed` is
# unchanged - and the printed fraction goes from 22 of 60 to 22 of 59,
# which reads as progress. The same edit is how a genuinely new reason
# gets lost: SDM Vol. 3D Appendix C grows, the table does not, and
# nothing says so.
#
# So this is exact in both directions. A row added deliberately raises
# it in the same diff; a row that vanished turns the job red and names
# the count it expected.
#
# Writing this down is what found the bug it exists for. The table had
# sixty rows against a report that called them "the 60 reasons in SDM
# Vol. 3D Appendix C"; counting Appendix C gives seventy-nine, and the
# nineteen missing ones were 5, 6, 41, 65, 67, 68, 69, 72-81, 84 and 85.
# Nothing in the job noticed, because every check reads the rows that
# exist. Worse, `session::observed_exit` was 72 wide and `note_exit`
# dropped anything above that, so reasons 72 and up could not have been
# recorded even if a processor produced one - and bus lock (74) is an
# ordinary exit on current hardware.
#
# 79 rows, counted from the `names` table in
# uefi_loader/src/guest_tests.cpp on 2026-08-12: reasons 0-4, 5-34,
# 36, 37, 39, 40, 41, 43-69, 72-81, 84 and 85. The gaps are encodings
# Appendix C does not define (35, 38, 42, 70, 71, 82, 83), not omissions.
rows=79
